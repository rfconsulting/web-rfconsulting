Cómo actualizar SQL Server Express con Advanced Services a SQL Server 2022

Una actualización segura empieza antes de abrir el instalador: compatibilidad, integridad, recuperación, ejecución controlada y pruebas reales.

RF ConsultingPublicado: 27 de agosto de 202612 min de lectura
Objetivo técnico

Destino: SQL Server 2022 (16.x)
Escenario: Express with Advanced Services
Modalidad: actualización in-place

Confirma siempre la documentación aplicable a la versión, edición y sistema operativo de tu entorno.

Conocer nuestra especialidad →

Antes de comenzar: una actualización in-place modifica la instancia instalada. Trabaja con una ventana de mantenimiento, respaldos restaurables y un plan de reversa documentado. En sistemas críticos, prueba primero en un entorno separado.

Actualizar SQL Server no consiste en presionar Next hasta llegar a Finish. Es un cambio de plataforma: primero se demuestra que el origen está sano y que la ruta es compatible; después se actualiza; finalmente se comprueba que los datos y las aplicaciones continúan funcionando.

1. Qué significa “Advanced Services”

En instalaciones heredadas, “SQL Server Advanced” suele referirse a SQL Server Express with Advanced Services. No es una edición independiente llamada Advanced: es una variante de Express que incorpora componentes adicionales, entre ellos Full-Text Search.

SQL Server Agent no forma parte de Express. Por eso conviene inventariar las funciones instaladas y no asumir que una característica existe solo por el nombre utilizado internamente para el servidor.

Si Setup muestra la página Full-text Upgrade, la instancia posee componentes de búsqueda de texto completo que requieren una decisión durante la actualización.

2. Confirma que la ruta de actualización es válida

SQL Server 2022 admite determinadas versiones de origen y exige niveles mínimos de Service Pack. La matriz de Microsoft incluye SQL Server 2012 SP4, 2014 SP3, 2016 SP3 y versiones compatibles de 2017 y 2019.

Para un origen más antiguo, o cuando se quiere una reversa más limpia, conviene evaluar una migración side-by-side: instalar una instancia nueva, restaurar las bases y mover los objetos de servidor necesarios.

No existe conversión in-place de 32 a 64 bits. SQL Server 2022 es x64. Una instancia de 32 bits requiere una nueva instalación x64 y una migración.

3. Haz un inventario antes de cambiar nada

Registra servidor, instancia, edición, versión, bases, modelos de recuperación y niveles de compatibilidad. Esta fotografía inicial facilita tanto la validación como una eventual reconstrucción.

SELECT
    @@SERVERNAME AS ServerName,
    SERVERPROPERTY('InstanceName') AS InstanceName,
    SERVERPROPERTY('Edition') AS Edition,
    SERVERPROPERTY('ProductVersion') AS ProductVersion,
    SERVERPROPERTY('ProductLevel') AS ProductLevel;

SELECT name, state_desc, recovery_model_desc,
       compatibility_level
FROM sys.databases
ORDER BY name;

También documenta cuentas de servicio, autenticación, protocolos, puertos, ubicación de archivos, logins, permisos e integraciones ODBC u OLE DB.

4. Identifica el uso de Full-Text Search

Advanced Services puede incluir búsqueda de texto completo, pero eso no significa que cada base la utilice. Revisa catálogos e índices dentro de las bases relevantes:

SELECT name, is_default, is_accent_sensitivity_on
FROM sys.fulltext_catalogs;

SELECT OBJECT_SCHEMA_NAME(object_id) AS SchemaName,
       OBJECT_NAME(object_id) AS TableName,
       is_enabled
FROM sys.fulltext_indexes;

Si ambas consultas quedan vacías, esa base no utiliza catálogos ni índices Full-Text. Conserva el resultado como parte del inventario.

5. Comprueba integridad y recuperación

Un upgrade no debe comenzar con una base cuyo estado se desconoce. Ejecuta DBCC CHECKDB y resuelve cualquier error de consistencia antes de continuar.

DBCC CHECKDB (N'MiBaseDeDatos')
WITH NO_INFOMSGS;

Luego crea un respaldo completo con checksum y verifícalo:

BACKUP DATABASE [MiBaseDeDatos]
TO DISK = N'D:\SQLBackups\MiBase_PreUpgrade.bak'
WITH INIT, CHECKSUM, STATS = 10;

RESTORE VERIFYONLY
FROM DISK = N'D:\SQLBackups\MiBase_PreUpgrade.bak'
WITH CHECKSUM;

La mejor prueba no es VERIFYONLY, sino restaurar el respaldo en otra instancia, abrir la base y ejecutar operaciones representativas de la aplicación.

6. Evalúa compatibilidad antes del upgrade

El componente de migración de SQL Server Management Studio permite ejecutar un Upgrade Assessment. Selecciona SQL Server 2022 como destino y analiza las bases que utiliza la aplicación.

Revisa cambios incompatibles, comportamientos modificados y funciones obsoletas. Este paso cobra especial importancia en sistemas contables, ERP, procedimientos almacenados, triggers e integraciones creadas para motores anteriores.

7. Ejecuta la actualización con una ventana controlada

Resuelve primero cualquier reinicio pendiente. Ejecuta setup.exe como administrador y elige la opción de actualización desde una versión anterior.

  1. Revisa términos de licencia, Global Rules y Product Updates.
  2. Permite que Setup actualice sus archivos y ejecute Upgrade Rules.
  3. Confirma cuidadosamente la instancia seleccionada.
  4. Revisa las características existentes; agrega funciones nuevas en otro cambio posterior.
  5. Verifica cuentas y configuración de servicios.
  6. Decide el tratamiento de Full-Text si aparece esa pantalla.
  7. Revisa el resumen, inicia el upgrade y conserva los logs de Setup.

Un instalador que termina no demuestra todavía que el cambio sea exitoso. La actualización concluye después de las pruebas.

8. Full-Text: Import, Rebuild o Reset

Setup puede ofrecer tres estrategias para los catálogos Full-Text. La elección depende del origen, la ventana disponible y el uso real de las búsquedas:

  • Import: conserva o importa los catálogos cuando el escenario lo permite. Suele reducir el trabajo inmediato.
  • Rebuild: reconstruye con los analizadores de palabras de la versión actual. Puede consumir tiempo, CPU y memoria.
  • Reset: restablece los catálogos y obliga a poblarlos después. Las búsquedas quedan incompletas hasta finalizar esa tarea.

En el procedimiento documentado se eligió Import para reducir el trabajo durante el upgrade. Esa decisión no elimina la validación posterior; si la aplicación usa Full-Text, prueba sus resultados y planifica una reconstrucción o población cuando corresponda.

ALTER FULLTEXT CATALOG [NombreCatalogo] REBUILD;

ALTER FULLTEXT INDEX ON [dbo].[NombreTabla]
START FULL POPULATION;

9. Valida el servidor y la aplicación

Confirma que el motor quedó en la rama 16.x, que todas las bases están ONLINE y que mantienen el nivel de compatibilidad esperado.

SELECT SERVERPROPERTY('Edition') AS Edition,
       SERVERPROPERTY('ProductVersion') AS ProductVersion,
       SERVERPROPERTY('ProductLevel') AS ProductLevel;

SELECT name, state_desc, user_access_desc,
       recovery_model_desc, compatibility_level
FROM sys.databases
ORDER BY name;

Ejecuta nuevamente DBCC CHECKDB y prueba autenticación, consultas, inserciones, procesos contables o de facturación, reportes, procedimientos, triggers, conectividad remota, servicios asociados y búsquedas Full-Text.

Finalmente, crea un nuevo respaldo completo. Ese archivo establece un punto de recuperación generado ya sobre el motor actualizado.

10. No cambies la compatibilidad a ciegas

La versión del motor y el nivel de compatibilidad de una base son controles distintos. Una base puede operar inicialmente en SQL Server 2022 conservando su nivel anterior.

Esta separación permite validar primero la plataforma y evaluar después el comportamiento del optimizador. SQL Server 2022 corresponde al nivel 160, pero el cambio debe realizarse con pruebas y seguimiento de Query Store.

ALTER DATABASE [MiBaseDeDatos]
SET COMPATIBILITY_LEVEL = 160;

Actualizar el motor y cambiar simultáneamente todas las bases a nivel 160 elimina una capa útil de aislamiento si aparece una regresión.

11. Diseña la reversa antes de necesitarla

El plan no puede ser “desinstalar 2022”. Una reversa real depende de respaldos, medios de instalación y la capacidad de reconstruir el entorno anterior.

  • Conserva versión, edición, Service Pack o CU y medio de instalación del origen.
  • Documenta instancia, autenticación, servicios, red y rutas de datos.
  • Exporta o documenta logins, permisos y objetos de servidor.
  • Define el punto máximo de pérdida de datos aceptable.
  • Prueba la restauración y el procedimiento de reconexión de la aplicación.

Para sistemas críticos, la migración side-by-side suele ofrecer una reversa más clara porque la instancia anterior puede mantenerse intacta hasta validar la nueva.

12. Checklist de RF Consulting

Antes: ruta compatible, requisitos, reinicio, inventario, Upgrade Assessment, CHECKDB, respaldos restaurables, configuración documentada y uso de Full-Text confirmado.

Durante: instancia correcta, reglas de Setup resueltas, cambios limitados al upgrade, decisión Full-Text consciente y logs conservados.

Después: versión 16.x, bases ONLINE, nueva comprobación de integridad, pruebas funcionales, revisión de logs, respaldo completo nuevo y compatibilidad 160 evaluada por separado.

Conclusión

Actualizar a SQL Server 2022 es un procedimiento manejable cuando sigue una secuencia clara: inventario, compatibilidad, integridad, respaldo, actualización, validación y solo después optimización.

La mejor actualización no es la que termina más rápido. Es la que permite demostrar que los datos, las aplicaciones y el plan de recuperación siguen funcionando al finalizar.
